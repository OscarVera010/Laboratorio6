Sincronización en la nube, ramas de desarrollo y trabajo en equipo.

Sincronización entre Git Local y GitHub

Párrafo 1: Mientras que Git es la herramienta de control de versiones que se ejecuta localmente en nuestra computadora, GitHub es una plataforma en la nube que aloja repositorios de Git de manera remota. Esto permite que múltiples programadores compartan un mismo proyecto, respalden su código en servidores seguros y colaboren desde cualquier parte del mundo sin enviar carpetas comprimidas manualmente.

Párrafo 2: Para comenzar a trabajar con un repositorio alojado en GitHub se utiliza el comando git clone <URL>, el cual descarga no solo los archivos actuales del proyecto sino toda su estructura de control de versiones (.git) y la vinculación automática con el servidor remoto llamado por defecto origin. Es fundamental clonar el repositorio en lugar de descargarlo como archivo ZIP, ya que el archivo ZIP pierde el historial y el seguimiento de versiones.

Párrafo 3: Una vez que hemos registrado commits en nuestra máquina local, empleamos git push para enviar nuestras confirmaciones hacia la rama principal (main) en GitHub. Asimismo, cuando agregamos colaboradores en la sección Settings → Collaborators de nuestro repositorio, nuestros compañeros pueden clonar el proyecto, incorporar mejoras o archivos nuevos, y subir sus propios commits compartiendo un flujo de desarrollo transparente y ordenado.

Comandos de Red en Git

Comando Función Principal
git clone <url> Descarga una copia completa de un repositorio remoto de GitHub.
git push Envía los commits locales hacia el repositorio remoto en GitHub.
git pull Descarga y fusiona los cambios realizados por otros colaboradores.
git remote -v Muestra las URLs asociadas al servidor remoto configurado.
